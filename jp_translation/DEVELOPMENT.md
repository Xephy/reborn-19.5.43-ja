# 開発メモ

Pokémon Reborn 日本語化パッチの内部資料。導入手順は [../README.md](../README.md)。

---

## 翻訳データの構造

`jp_translation/work/src/*.jsonl` が翻訳のソース。1行1エントリ。

```json
{"sec": "map:37", "key": "AME: Thank goodness, you're okay!", "en": "AME: Thank goodness, you're okay!", "ja": "アメ: よかった、無事だったのね!"}
```

- `sec` — messages.dat 内のセクション。数値は固定セクション（1=種族名, 5=わざ名 …）、
  `map:N` はマップ N の会話
- `key` — 元の英語文字列。Essentials の `_INTL` / `_MAPINTL` はこれをキーに実行時に引く
- `ja` — 訳文。空なら未訳で、その行は英語のまま表示される

**すべてのセクションが「英語テキストをキーにした Hash」**なので、インデックスのずれが
構造的に起こらない。部分的な翻訳のまま出荷しても壊れない。

追加でこのプロジェクトが足したソースファイル:

| ファイル | 内容 | 件数 |
|---|---|---|
| `22b_field_notes.jsonl` | フィールドノートの見出し・詳細・フィールド名 | 882 |
| `22c_system_texts.jsonl` | `_INTL` を通っていなかったシステム文言 | 176 |
| `22d_field_messages.jsonl` | `fields.dat` のバトル中フィールドメッセージ | 229 |
| `22e_pulsedex.jsonl` | パルス図鑑の一覧エントリ名 | 14 |
| `22f_bt_speeches.jsonl` | バトルタワー系トレーナーのセリフ | 1,154 |
| `22h_interp_keys.jsonl` | Ruby 補間 `#{...}` を含んでいた `_INTL` 文字列の正しいキー | 38 |
| `22j_event_scripts.jsonl` | マップイベントの「スクリプト」コマンド内に書かれた `_INTL` / `_I` 文字列 | 8 |
| `13b_bt_trainer_names.jsonl` | 同トレーナーの名前（セクション13） | 309 |

`22j` の1件（化石復元の `_I`）だけはセクション0（マップ242のハッシュ）に入る。
残りはすべてセクション22（スクリプトテキスト）に足している。`_INTL` は未知のキーを
そのまま返すので、英語版の表示は影響を受けない。

## Reborn 特有の落とし穴

翻訳漏れの大半は「訳が無い」ではなく「**訳しようがない**」だった。
種類ごとに整理する。同じ検査は
`python3 jp_translation/tools/find_untranslated.py` で再現できる。

### 1. データ由来の名前が表を引き直していない

ポケモン名・わざ名・どうぐ名は会話文と違って `_INTL` を通らない。ゲームデータ側の
オブジェクトが英語名を持っていて、表示のたびに `getMoveName` などが
messages.dat のハッシュを引き直す仕組みになっている。
**この引き直しを飛ばして英語名を直接描いている箇所があると、そこだけ英語のまま残る。**

バトルのわざ選択がそれで、`PokeBattle_Move#name`（生成時にデータの英語名を
コピーしたもの）を描いていた。`Battle_Move.rb` で生成時に翻訳名を入れるよう変更し、
英語名が必要な2箇所——ボスのチャージ技の一致判定と `BattleData` のわざ使用回数の
集計キー——だけ新しい `englishName` を参照する。

性格名は専用セクションが存在せず（`compileNatures` は natures.dat を書くだけ）、
性格変更メニューの `_INTL` リテラル経由でセクション22に入っている。
`getNatureName` をそこから引くようにした。

### 1b. データオブジェクトの名前を表引きせずに使う

`$cache.items[item].name` などはデータ側の**英語名**そのもの。表を引くのは
`getItemName` / `getMonName` / `getMoveName` / `getAbilityName` / `getTypeName` の
アクセサだけで、生で参照した値が画面に出ると英語のまま残る。

**`Kernel.pbMessage` の `pbLocalize` では救えない。** あれが引き直すのは
セクション22（スクリプトテキスト）で、どうぐ名はセクション7、種族名はセクション1と
別の表にあるため。

実際に3件あった。

| 場所 | 症状 |
|---|---|
| `Items.rb` `pbChooseItemFromList` | むしよけスプレーが切れた時の選択肢が `Repel` / `Super Repel` / `Max Repel` |
| `Reborn/RebornScripts.rb` | 最初のポケモン確認の「それは {1}、{2}ポケモンだね!」の種族名だけ英語 |
| `Storage.rb` | PCの検索で持ち物だけ英語名と照合していて、日本語で検索しても当たらない |

`find_untranslated.py` が `$cache.<表>[...].name` の生参照を検出する。英語のままで
正しいもの（アクセサ本体、`TM94` から数字を取り出す並べ替え、開発者向けのエクスポート、
読み上げ）は理由つきで許可リストに入れてある。

### 1c. トレーナーの手持ちのニックネーム

`PokeBattle_Pokemon#initialize` は `@name = getMonName(@species, @form)` で**訳された
種族名**を入れるが、`Trainers.rb` が直後に

```ruby
pokemon.name = poke[:name] if poke[:name]
```

で `trainers.dat` の**生の英語ニックネーム**を上書きする。

**37トレーナー・404体・229種類**ある。テーマごとに命名されているので、まとめて
訳さないと不自然になる（アマリアは雲と沈んだ大陸、アドリエンヌはケルトの妖精、
ルナは不思議の国のアリス、ジュリアは擬音、イカルとクリムは星、テラはネット語）。

字形そのものが内容の11件（`CL:4R1-C3` のリート表記、`:)` の顔文字、`No.1`〜`No.6`）は
英語のまま残す。カタカナにすると成立しなくなるため。

名前欄は約194pxだが、性別記号が名前の直後に置かれるので **160px** を上限にした
（英語の最長 `SCROOGEMCFUCK` が156px）。ニックネームが付いた個体は
バトル中の表示（データボックス、くりだしメッセージ、`pbThis`）が全部そこを見るので、
種族名の訳がいくら揃っていても英語で出る。

**37トレーナー・229種類**のニックネームがある。シェリーのメガヤンマ (`Heather`) と
バルビート (`Bugsy`) がこれ。代入を `_INTL` に通し、キーはセクション22へ手で足す
（変数なのでコンパイラは登録できない）。訳が無いものはそのまま英語で返る。

### 2. `_INTL` を通っていない素の文字列

messages.dat に載るのは、スクリプト中の `_INTL("...")` / `_ISPRINTF("...")` の
**リテラル**をコンパイル時に拾ったものだけ。素の文字列をそのまま
`Kernel.pbMessage("...")` に渡している箇所は表にキーが存在せず、永久に英語のまま。
Reborn には150件ほどあった。

- `Kernel.pbMessage` / `pbMessageChooseNumber` / `pbMessageFreeText` が、受け取った
  文字列（と選択肢の配列）を表で引き直すようにした（`Kernel.pbLocalize`）。
  訳済みの文字列はキーではないのでそのまま返る。呼び出し側を触らずに83件を回収
- オプション画面の説明文はオプションに素の文字列として持たせてあるので、
  テキストボックスへ渡す直前で引く
- チャンピオン防衛戦の挑戦者のセリフは `$game_variables` に代入されてから
  `\v[n]` で表示されるので、代入時に `_INTL` を通す
- 文字列連結や `#{}` で組み立てているものはどうやってもキーにならないので
  `_INTL("...{1}...", 変数)` の形に書き換えた

### 2c. テキストが第1引数ではない補助関数

`UIHelper.pbChooseNumber(helpwindow, 'How many do you want to use?', max)` のように、
**表示文字列が第2引数**に来る補助関数がある。`pbMessage` 系の第1引数だけを見ていた
検査はこれを拾えず、しかも単一引用符なのでコンパイラにも登録されていなかった。
アメ類・栄養ドリンク・きのみなど `ItemHandlers::MultipleAtOnce` の個数を聞く場面で
英語のまま出ていた。

`find_untranslated.py` は `pbChooseNumber` / `pbInputNumber` / `pbShowCommands` /
`pbChooseList` / `pbChooseItemFromList` を呼ぶ行について、**引数の位置を問わず**
すべてのリテラルを見る。`@sprites["msgwindow"]` のような添字は除外している。

### 2d. `#{}` で組み立てたテンプレート

`Battle.rb` の壁・補助効果が切れるメッセージ8種がこれだった。

```ruby
texts = ["Your", "The opposing"]
pbDisplay(_INTL("#{texts[i]} team's Light Screen faded!"))
```

`#{}` は `_INTL` に渡る**前**に展開されるので、コンパイラが登録するのは
`#{texts[i]} team's Light Screen faded!` という文字列そのもの。実行時のキーは
`The opposing team's Light Screen faded!` で、**永久に一致しない**。

側を表す語を完全な語にして `{1}` で渡す形に書き換えた。英語の出力は元と同一。

```ruby
texts = [_INTL("Your team"), _INTL("The opposing team")]
pbDisplay(_INTL("{1}'s Light Screen faded!", texts[i]))
```

対象はリフレクター／ひかりのかべ／オーロラベール／アレナイトウォール／
しんぴのまもり／しろいきり／おいかぜ／おまじないの8種。

`find_untranslated.py` は以前からこれを「実行時に組み立てられるキー」として
報告していたが、報告の中に `_INTL(変数)` の正常な用法（`fields.dat` の文字列など）が
多数混ざるため埋もれていた。**`#{` を含むものは常に不具合**なので、そこだけ拾って
確認するとよい。

補間される値の取りうる範囲が閉じている場合は、スクリプトを書き換えずに
**展開後のキーを全通り登録する**ほうが安い。どうぐ入手時の

```ruby
_INTL("{1} put the \\c[1]{2}\\c[0]\r\nin the <icon=bagPocket#{pocket}>\\c[1]{3}\\c[0] Pocket.", ...)
```

は `pocket` が `pbPocketNames`（`Reborn/Settings.rb`）の 1〜8 に限られるので、
`22h_interp_keys.jsonl` に 8 ポケット × 単数/複数の 16 件を入れて解決した。
`Scripts/Field.rb` を配布物に足さずに済む代わりに、**ポケットが増えたら追随が要る**。
`Settings.rb` 自体をこのプロジェクトが配布しているので、そこが変わったときに気付ける。

なお `build.py` はハッシュ節に対して `messages.dat` に無いキーも受け付けるため、
この手の追加は新しい `*.jsonl` を 1 枚置くだけでよい。キーは実行時の生文字列
（`\r\n` のまま）を書けばよく、`string_to_key` の正規化は `build.py` が行う
—— Ruby の `^`/`$` は行アンカーなので `\r\n` は空白1個ではなく `\n` になる点に注意。

補間される値がポケモン名やボックス名のように**開いている**場合はキーを列挙できない。
`apply_script_patches.py` の `INTERP_EDITS` にスクリプト書き換えを宣言してある。

| ファイル | 内容 |
|---|---|
| `Battler.rb` | レッドカード／だっしゅつボタン／だっしゅつパック／からぶりほけん／のどスプレー |
| `Battle_MoveEffects.rb` | アロマベール6種、ルームサービス、いのちがけ失敗時の2行、`Congratulations,`（`CELEBRATE`） |
| `ItemEffects.rb` | 努力値の入れ替え・上昇の確認メッセージ |
| `Storage.rb` | ボックス並べ替えの確認（三項演算子が `_INTL` の**中**にあり、どちらの分岐も引けなかった） |

置換テキストをマーカーに使えないものが1件ある。`{1} protected itself!` は
他5箇所で既に使われているので、`new` がファイルに元から存在し「適用済み」と
誤判定される。囲みの `if` ごと置換対象にして一意にしてある。

翻訳文は `#{}` 付きのキーに対して既に入っていたので、式→`{n}` の対応をそのまま
移した。ただし Aroma Veil の `from being blocked!` は
`Block`（とおせんぼう）ではなく **`Heal Block`（かいふくふうじ）** の
`PokeBattle_Move_0BB` なので、「封じ込め」から訳し直した。

未対応で残しているもの:

* `Online/Trade.rb`・`Online/Connect&Register&Login&New.rb` の21件。
  オンライン対戦・交換専用で、コミュニティのサーバーが要るため実機確認ができない。
  うち8件は `_INTL("#{pkmn.name}")` のように**訳す語が無い**ただの包み方の誤りで、
  `{n}` 化しても意味がない。
* `MinigameTilePuzzles.rb:173` の `_INTL("Graphics/Pictures/Tile Puzzle/tiles#{@board}")`。
  これは表示文字列ではなく**画像のパス**。訳してはいけないので `#{}` のままでよい。

### 3. 訳文に英語の部品が差し込まれる

テンプレート自体は訳せていても、`{1}` `{2}` に埋める部品が英語だと結局まざる。
バトルのステータス変化がそれで、`pbGetStatName` が
`["HP", "Attack", ...]` というベタ書きの配列を返していた。「{1}の{2}が上がった!」の
訳はあるのに「リザードンのAttackが上がった!」になる。同じ理由で
`"sharply "` `"harshly "` の副詞、`STATSTRINGS`（どうぐの能力値表示）も英語だった。

副詞は日本語では動詞の直前に来るので、テンプレートの訳を
「{4}が{3}上がった!」の語順にしたうえで部品を訳す（ぐーんと／ぐぐーんと／
がくっと／がくーんと）。

### 2b. ビットマップへ直接描かれる文字列

`Kernel.pbMessage` 系を通らず `pbDrawTextPositions` でビットマップに直接描く文字列は、
メッセージ関数の呼び出しですらないので **2. の検査にも引っかからない**。操作設定の
キーボード／ゲームパッド一覧（`Controls.rb`、48行）が丸ごとこれだった。

描画ヘルパは `["文字列", x, y, ...]` の配列を受け取るので、`find_untranslated.py` は
**描画を行うファイル内の「文字列で始まる配列リテラル」**を拾うようにしてある。
`pbDrawImagePositions` が同じ形で画像パスを渡してくるため、`/` を含むものと拡張子つきは
除外する。

この検査で `Load.rb` のセーブ選択画面（`Normal Save` / `Autosave`）と、オープニングの
切符に印字される `Grandview Station` も見つかった。いずれも描画箇所を `_INTL` に
通してキーを追加した。切符の `ONE` / `SGL` は券面の略号（`8R750` `5D` と同列）なので
英語のまま残し、ツール側に理由つきで除外を書いてある。

一覧は2段組みで、2列目の実効幅は 228px（キーボード）/ 248px（ゲームパッド）しかない。
訳文は各行の実際の列幅に対して検証すること。なお英語版もこの2列目は3行はみ出している。
`クイックセーブ` は2列目に収まらないため、1画面内で用語が割れないよう全体を
`即セーブ` にそろえた。

### 3b. 登録されたキーと引かれるキーが食い違う

`pbAddRgssScriptTexts` はソースの文字列を単純な `gsub` の連続でアンエスケープする。
そのため**エスケープされたバックスラッシュを含むリテラル**は、コンパイル時に登録される
キーと、実行時に Ruby が組み立てる文字列が一致しない。`"...\\n..."` は Ruby にとって
「バックスラッシュ + n」だが、コンパイラは改行に変換してしまう。訳をどう書いても
永久に引けない。

Reborn 全体で3件あった（フィールドでの毒の耐えきりメッセージ、隠しアイテムの
入手メッセージ2種）。実行時のキーで登録し直して解決。`find_untranslated.py` が
この食い違いも検出する。

### 3a. シングルクォートのリテラルは拾われない

`pbAddRgssScriptTexts` の正規表現はダブルクォートのリテラルしか見ない。
`_INTL('...')` と書かれていると、`_INTL` を通しているのにキーが登録されない。
Reborn には27件あった（パスワード系、休憩・時間待ち、にじいろのかおり）。
実行時は普通に表を引くので、キーを足すだけで直る。`find_untranslated.py` が
シングルクォートの `_INTL` とメッセージ呼び出しも拾うようにしてある。

### 3c. 桁揃えの空白がキーに混ざる

バトルの Inspect 画面は能力値のラベルを空白で桁揃えしていた
（`"Attack:               "` + `"{1}  "`）。この文字列がそのまま `_INTL` に渡る。
`stringToKey` は前後の空白を落とし連続空白を1つに畳むので、キーは `Attack: {1}` に
なる——つまり**ソースの空白はキーに影響しない**。訳側に自前の空白を入れれば桁は
そろうし、訳が無ければ元の英語（空白込み）がそのまま返るので英語表示も変わらない。
コードを触らずにキーを足すだけで済む。

同じ画面で `(_INTL "Inspecting {1}:", pkmn.name)` という書き方もあった。括弧が
呼び出し名の前にあるため Reborn 自身のスクレイパの正規表現に引っかからず、キーが
登録されていなかった。`find_untranslated.py` はこの書き方も拾う。

### 3e. マップイベントの「スクリプト」コマンド内のリテラルは拾われない

化石復元の研究員（スピネル博物館2階）に話しかけると、持ち物を選ばせるプロンプトだけが
英語のままだった。イベントの中身はこう書かれている。

```ruby
pbChooseItemFromList(
_I("Do you have a fossil for me to
revive?"),16, :HELIXFOSSIL, ...)
```

`_INTL` を通しているのに `messages.dat` にキーが無い。Reborn のコンパイラが登録するのは
**スクリプトファイルの中のリテラル**と**マップの「文章の表示」コマンド**の2つで、
マップイベントが自前で持つ Ruby（コマンドコード355、続きが655）は
どちらにも当たらないため。3a と同じ「呼び方は正しいのにキーが無い」型で、
原因はクォートではなく**書かれている場所**。

引く先は呼び方で変わる。`_INTL` はセクション22、`_I` は
`_MAPINTL($game_map.map_id, ...)` なので**そのマップのハッシュだけ**で、
セクション22はフォールバックにならない（`PBIntl.rb` の `getFromMapHash`）。
化石の1件だけが `map:242`、残りはセクション22に入れてある。

`find_untranslated.py` が `Data/Map*.rxdata` のスクリプトコマンドを走査し、
リテラルごとに**その呼び出しが実際に引く表**と突き合わせて報告する。
足す前は17か所（9種）、足したあとは0件。

### 3d. あとから読まれるスクリプトが同じクラスを開き直す

フィールドノートの一覧は `FieldNotes.rb` の `Scene_FieldNotes#buildFieldMenu` を
直しても英語のままだった。`Reborn/RebornPokegear.rb` が同じクラスを開き直して
`buildFieldMenu` を丸ごと差し替えており、SCRIPTS の並びでこちらが後に読まれるため。
分類見出し付きの別実装で、フィールド名を `$cache.FEData[field].name` から直接
取っていた。**同名のメソッドを直すときは、後続のスクリプトが開き直していないか
確認する。**

### 4. 表はあるのに誰も読んでいなかったセクション

トレーナーの負け台詞は専用セクションに771件そろっていたのに、実際に画面へ出す
`Battle.rb` だけが `@endspeech` をそのまま描いていた（`Trainers.rb` のスキップ表示は
ちゃんと引いていた）。`pbTrainerSpeech` を足して、セクション16 →
スクリプトテキストの順に引くようにしてある。後者はオーガナイズドバトルが
リテラルを代入してくるため。

バトルタワー系のセリフは `bttrainers.dat` にあり、そもそもどのセクションにも
登録されていなかったので、キーごと追加した（1,053件）。対戦前のセリフだけは
ゲーム変数に入れて `\v[n]` で出すため表を通らないので、`pbBattleChallengeBeginSpeech`
の戻り値を `_INTL` に通している。

地名（マップ名）は `MapInfos` からセクション20へ書き出されていたのに、**読み出す側が
1つも無かった**。`Game_Map#name` も `pbGetBasicMapNameFromId` も
`$cache.mapinfos[id].name` を直接見ていたため、エリア移動時の看板・セーブ画面・
ポケモンの「出会った場所」が全部英語のままだった。訳自体は851件そろっていたので、
この2つを `pbGetMessage(MessageTypes::MapNames, id)` 経由にするだけで直った。

`Field.rb` の「直前のマップと同じ名前なら看板を出さない」判定も同じ関数を使うよう
そろえてある（片方だけ訳されると比較が成立しなくなるため）。

### 4b. マップイベントがゲーム変数に入れるトレーナー情報

大ホールの手合わせ相手は、マップイベントの**スクリプト行**でトレーナーを組み立てる。

```ruby
$game_variables[601] = "JB"
$game_variables[602] = :EXPERT_Male
$game_variables[603] = "Not bad. Apparently I have something to work on."
```

消費側（コモンイベント79「Grind Trainer」）は

```ruby
pbTrainerBattle(pbGet(602), pbGet(601), _I(pbGet(603)), false, pbGet(600))
```

と `_I` で引いているので**実行時は表を通る**。ところが代入側が `_I("...")` ではなく
素の文字列なので、マップテキストのコンパイラがキーを登録しない。**引く側はあるのに
登録される側が無い**状態で、訳を書く場所そのものが存在しなかった。

`_I` は `_MAPINTL($game_map.map_id, str)` なので、キーは**戦闘が始まるマップの節**に
足せばよい。大ホール（map 38）に10件あった。コードは触らずに済む。

### 4c. 手で足したマップ節のキーは実行時に引かれないことがある

4b の敗北セリフは、マップ38の節にキーを足しただけでは**実機で英語のままだった**。
同じファイルのセクション22に同じ訳を入れたところ日本語になったので、マップ節の
経路が通っていない。

Reborn 自身のコンパイラは、マップ中の**メッセージコマンド**からキーを登録する。
今回の文字列はスクリプト行でゲーム変数へ代入されるだけなので、そのコンパイラを
通っていない。手で足したキーは元テーブルに存在せず、実行時に引かれないことがある。

**確実な経路はセクション22。** `pbTrainerSpeech` はセクション16で外れたときに
`_INTL` で引き直すので、そこに入れておけばマップ節に依存しない。

`find_untranslated.py` が **元の `messages.dat` に無いマップ節キー**を検出し、
セクション22に同じキーが無ければ報告する。現状は10件すべて両方に入っていて0件。

なお「マップ節が絶対に効かない」と断定はできない。実機で古い表を掴んでいた可能性を
完全には排除できていないため、あくまで**両方に入れる**運用にしてある。

**追記（ja.10）**: 3e の化石復元は `map:242` にキーを足しただけで実機で日本語になった。
マップ節そのものは生きている。4c が効かなかったのは `pbTrainerSpeech` が
セクション16と22しか見ずマップ節を引かないからで、経路の問題だった。
とはいえ引く先は呼び出し側ごとに違うので、**どの関数がどの表を見るかを確かめてから
入れる**——これが上の運用の本来の意図。

### 5. 一度だけコンパイルされて全言語で共有されるデータ

フィールドノートの本文は `Reborn/FieldNoteCompiler.rb` の中の英語リテラルで、
初回起動時に `Data/fieldnotes.dat` へ書き出されて以降は再生成されない。フィールド名も
同様に `Data/fields.dat` に固まる。**この2つは全言語で共有される**ので、中身が言語に
依存してはいけない。素の実装は本文の一部を `getMoveName` / `getTypeName` で埋めており、
日本語で初回起動すると訳語が焼き付くうえ、`<icon=typeでんき>` という存在しない
アイコン名になってタイプアイコンが消える。`feMoveName` / `feTypeIcon` を足して英語で
固定した（パッチ後も出力が既存の .dat とバイト一致することを Ruby で確認済み）。

そのうえで表示直前に `_INTL` を通す（`fieldNoteName` / `fieldNoteText` /
`fieldNoteElaboration`）。キーは英語の原文そのまま。`Wasteland` と `Cave` はPCボックスの
壁紙名として既にセクション22にあるので、そちらの訳を共有している。

`fields.dat` のバトル中フィールドメッセージは `_INTL(変数)` の形で表示されているので、
キーを足すだけで直る。言い回しは旧版の館内資料（`map_0428`）に合わせてある。

### 5b. 表示文字列がそのままアセットのファイル名になっている

ポケギアの「時間と天気」は、天気の名前を `_INTL("Clear")` などで取得したうえで

```ruby
setBitmap(sprintf("Graphics/Pictures/Pokegear/TimeWeather/weather_%s", @weatherType))
```

とファイル名に埋めていた。10語すべてに訳が入っていたため、パスが
`weather_晴れ` になって存在しないファイルを指す。`GifBitmap#initialize` は読み込み
失敗を `rescue` して `nil` にするので、**エラーも出ず天気アイコンが黙って消える**。
配列を英語のリテラルに戻して、表示する箇所で訳す方式にした（`feMoveName` と同じ考え方）。

**表示に使う文字列がアセットのキーを兼ねていないか**は、訳を入れる前に確認する。

### 5c. strftime の曜日・月名

同じ画面の日付は `time.strftime("%a  %e  %b")` で組み立てられていた。Ruby の
`strftime` はロケールを見ず常に英語を返すので、表を通さない限り英語のまま残る。
部品（`Sun`〜`Sat`、`Jan`〜`Dec`）と並び順のテンプレートを別々にセクション22へ入れ、
日本語では `{3}{2}日 ({1})` に組み替えている。時間帯の `Day` / `Night` /
`Evening` / `Morning` は素の文字列だったのでキーごと追加した。

### 6. 文字が絵に焼き込まれているもの

タイプは文字列ではなく 64x28 の画像で、`Graphics/Icons/typeFIRE.png` のように
タイプ名が描き込まれている。日本語版の画像を `patch/Graphics/Icons/ja/` に置き、
`pbResolveBitmap` が日本語のときだけ同名ファイルの `ja/` 版を先に探すようにした。
呼び出し側（約30箇所）を1つも触らずにすみ、フィールドノートの `<icon=typeFIRE>` にも
同時に効く。結果はセッション中キャッシュするので、画像1枚につきディスクを見るのは1回。

ポケモン図鑑のタイプバッジ（96x32、`Graphics/Pictures/Pokedex/pokedex<TYPE>.png`）も
同じ作りで、バトル用の 64x28 とは別物。`build_type_icons.py` が両方をまとめて生成する。
地の色を拾うときはラベルの上2行だけを見る——英単語が長いバッジでは白い文字の画素が
地の色を上回り、ボックス全体の最頻色を取ると白く塗り潰してしまうため。

状態異常バッジ（44x16、ねむり／どく／やけど／まひ／こおり／ひんし）も同じ作り。
同梱フォントはピクセルフォントなので、設計サイズちょうどならアンチエイリアスを
切って原画と同じ質感で描ける。縮めると線がつぶれるため、縮めたものだけ
アンチエイリアスを掛ける。`ポケルス` は4文字で、読めるサイズにならなかったので
`PKRS` のまま残してある。

図鑑と検索画面の枠にある `EXIT` `NAV` `SEARCH` は背景が単色でないので手を付けていない。

バトルの行動選択（たたかう／バッグ／ポケモン／にげる）も 260x414 のシート1枚に
9コマンド x 2状態が描き込まれている。プレートは水平な帯の重なりなので、文字の左右

このシートは Reborn 側が `_INTL(パス)` で読んでいる——Essentials が言語ごとに画像を
差し替えるための仕組み——ので、パスを訳としてセクション22に入れるだけで切り替わる。
コードは1行も触っていない。

パルス図鑑のページも1件1枚の 512x384 画像で、タイトル・タイプ・とくせい・説明文が
すべて描き込まれている。こちらは `IconSprite#setBitmap` が `pbResolveBitmap` を
通らないので、呼び出しを `pbBitmapName` 経由にしてある。

画像はどちらも英語版を下敷きに生成する（`build_type_icons.py` /
`build_pulsedex_images.py`）。文字の乗る範囲だけを地の色で塗りつぶし、同じ色と影で

## 作業フロー

```
extract.py      messages.dat  →  work/src/*.jsonl
make_batch.py   未訳行を抽出  →  work/batch/gN/gN_XXXX.tsv   (id, 話者, 英文)
                （翻訳作業）  →  work/answers/gN_XXXX.tsv    (id, 訳文)
apply_batch.py  訳文を書き戻し（id指定なので他ファイルを汚さない）
dejoyo.py       常用外漢字を一括で仮名／常用漢字の同義語へ
build.py        work/src/*.jsonl  →  patch/Data/japanese.dat（書き出し後に読み直して検証）
sync.sh         パッチ一式を実機へ配布
```

チェックポイントは必ず `apply_batch.py → dejoyo.py → build.py → sync.sh` の順。

リリースは `make_release.py <タグ>` で `dist/` に zip を作り、タグを打って
GitHub Releases に添付する。zip の中身は `sync.sh` の配布リストから組み立てるので、
実機へ配るものと配布物が食い違うことはない。

`make_release.py` は zip を作ったあと、作成者を特定できる文字列が混入していないかを
検査する。アカウント名は実行時に機械から取り、それ以外は `/home/<名前>` や
`C:\Users\<名前>` といったパスの形で捕まえる（検査したい名前を公開ファイルに
書かずに済ませるため）。追加したい語は環境変数 `REBORN_JA_SCRUB` で渡す。
見つかった場合は zip を削除して異常終了する。

差し戻し用の原本が1本でも欠けていると `make_release.py` は止まる。原本が
**現行の Reborn と同一か**までは見ないので、本体が更新されたら
`check_backups.py --download` を回して確認する。

`sync.sh` は Windows 版と Linux（AppImage）版の両方へ配る。
配布先のパスはスクリプト冒頭の `WIN` / `LIN` を書き換える。

### 書き戻し時の検証

`apply_batch.py` は各行について次を検査し、通らない行は**書き込まずに報告**する。

- プレースホルダ・制御コード（`\PN` `\v[12]` `\c[3]` `\ch[...]` `{1}` …）が
  英文と同じ多重集合であること
- `--tags` を付けると `<icon=...>` `<c=...>` などのマークアップも同様に照合する
  （フィールドノート用。タグが密で、落としても気づけないため）
- 訳文が英文のままでないこと（記号・数字・略号・ゲーム内の文字化け演出は除外）

プレースホルダには例外が2つある。**`\PN`（主人公名）は原文より多く使ってよい**——引数を
持たず表示時に名前へ展開されるだけで、日本語の語順では英語の "you" の位置に名前を置く
ほうが自然なため。逆に欠けている場合は従来どおり拒否する。**`\tts[...]`（読み上げ用の
別読み）と `\ch[...]`（選択肢メニュー）の括弧内は比較対象外**——どちらも画面に出る本文
であり、訳文と一緒に翻訳されるため。

答案ファイルは行単位ではなく**レコード単位**で読む。原文に改行を含む行があり、
1レコードが複数行にまたがるため（`id<TAB>` で始まらない行は前の行の続きとみなす）。

### Ruby の構文検査

`apply_script_patches.py` は、その実行で書き換えたファイルを**ディスクに書く前に**
`ruby -c` に通す。**スクリプトが1つでも構文エラーだとゲームが起動しなくなる**ため、
1件でも落ちたら**何も書かずに中止して exit 1** する。中途半端に当たった木より
未適用の木のほうがましだから。

```
  ** 構文エラー  Scripts/RegionMap.rb
                 Scripts/RegionMap.rb:628: syntax error, unexpected end-of-input, expecting `end'

1 ファイルが壊れているため、書き込みを中止しました。
```

一時ファイルに書いて検査するが、エラー中の一時パスは本来のパスに置換して表示する。

`ruby` が PATH に無ければ**注意を出して飛ばす**（この検査のためだけに Ruby を必須には
しない）。`--no-syntax-check` で明示的に無効化、`RUBY=/path/to/ruby` で任意の実行系を指定できる。

検査するのは**構文だけ**。RGSS のクラスは存在しないので実行はせず、
`Window_CommandPokemon.newWithSize` の引数順のような **API の誤用は検出できない**。
そこは実機で見るしかない。

導入は sudo 不要。Ruby 本家が CI 用に配っているビルド済み tarball を使う。
apt の Ruby は 3.0 だが、mkxp-z が積んでいるのは **3.1**（`x64-msvcrt-ruby310.dll`）なので
そちらに合わせてある。

```bash
curl -L -o /tmp/ruby.tar.gz \
  https://github.com/ruby/ruby-builder/releases/download/toolcache/ruby-3.1.6-ubuntu-22.04.tar.gz
tar xzf /tmp/ruby.tar.gz -C ~/.local && mv ~/.local/x64 ~/.local/ruby-3.1.6

cat > ~/.local/bin/ruby <<'EOF'
#!/bin/sh
RUBY_HOME="$HOME/.local/ruby-3.1.6"
export LD_LIBRARY_PATH="$RUBY_HOME/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
exec "$RUBY_HOME/bin/ruby" "$@"
EOF
chmod +x ~/.local/bin/ruby
```

このビルドは rpath を持たないので、同梱の `libruby.so.3.1` を
`LD_LIBRARY_PATH` で指す必要がある。上のラッパーはそれを隠すためのもの。
展開後で 62MB、ゲーム本体とは無関係な `~/.local` 配下なのでリポジトリは汚れない。

## 翻訳の方針

`work/TRANSLATE_GUIDE.md` に全文。要点のみ:

- ポケモン・わざ・どうぐ・分類名は**公式日本語名**。用語集は
  `work/glossary.json`（ゲームデータから生成）と `work/glossary_extra.json`（会話にしか
  出ない補遺）。**用語集に無くても実在するものは公式名を使う**——glossary.json は
  ゲームのデータから作っているので、会話中でしか言及されない第9世代のポケモンなどは
  載っていない
- Reborn オリジナルの固有名詞は自然な日本語に訳す
- **常用漢字のみ。** 表外漢字は `dejoyo.py` が一括処理するので手で直さない
- 全角スペース（U+3000）を単語区切りに使わない（表示幅の節約）
- 口調は `TRANSLATE_GUIDE.md` の表に確定分をまとめてある
- メッセージウィンドウは2〜3行。原文が短ければ訳も短く
- 罵倒・下品な表現は強度を落とさない（原作の性格描写のため）

## リポジトリの構成

リポジトリのルートはゲームのインストール先そのもの。`.gitignore` はホワイトリスト方式で、
`/*` で全体を除外してから必要なパスだけを戻している。ゲーム本体（Audio / Graphics /
Data / エンジンDLL）は含まれない。`Scripts/` もディレクトリごとではなく、改変した
37ファイルだけを名指しで許可している。ルートに新しいファイルを置くときは
`.gitignore` に `!` 付きで追記しないと無視されるので注意。

改変前のスクリプトは `backup/19.5.43-scripts/` にある。配布している28ファイルすべてが

（`pbDrawTextFitted`）を取り除いて復元したもの。

## patch/Mods/ 方式への移行（検討結果）

Reborn 同梱の `Modding.txt` は、base game のファイルを差し替えるのではなく
`patch/Mods/*.rb` に置くことを推奨している。`Scripts/ScriptLoader.rb:108` が

```ruby
# Load script mods
Dir["./patch/Mods/*.rb"].each do |file|
```

で読み込む。**現時点の本パッチは `Scripts/` の37本を丸ごと差し替えており、この方針に
沿っていない。**

### 実行順序

`ScriptLoader.rb` の順序は次のとおり。

| 行 | 処理 |
|---|---|
| 102-105 | `SCRIPTS.each` — base game のスクリプトを全部ロード |
| 108-110 | `patch/Mods/*.rb` をロード |
| 114 | `mainFunction` → `mainFunctionDebug` → `startup`（`Main.rb:31`） |

Mod は **base の全ロード後・ゲーム開始前**に読まれる。したがってクラスを開き直して
メソッドを再定義すれば、そのメソッドだけが置き換わる。

### 移行可能性

**ロード中に実行される行と、本パッチの変更行の交差は 0 件だった。**
言語まわりで唯一気になる `pbSetLanguage` は `ClientData.rb` の `def startup` の中に
あり、`LANGUAGES` の参照箇所もすべてメソッド内なので、Mod による後からの上書きが間に合う。
`LANGUAGES` 定数の再定義は Ruby の警告を出すが、`Reborn/Settings.rb:334` で
`$VERBOSE = nil` になっているため表面化しない。

| 指標 | 値 |
|---|---|
| 差し替えているファイル | 37本 |
| 再定義が必要なメソッド | 101個 |
| ロード時に実行される変更行 | **0** |

### 効果と限界

メソッド単位の上書きでも、**変更していない行も含めてメソッド全体を書き写す必要がある**。
つまり Reborn のコードが配布物から消えるわけではなく、量が減るだけ。

| | 行数 |
|---|---|
| 現在配布しているファイル全体 | 約 68,000 |
| 書き写しが必要なメソッド本体 | 約 13,500 |

**削減率はおよそ 80%**（概算。ネストしたメソッドの数え方で誤差がある）。
`Battle_MoveEffects.rb` は 10,957 行のうち **1メソッドで 4,042 行**あり、これを丸写しする
ことになる。ここは移行の費用対効果が最も悪い。

### 結論: 見送り

技術的には可能だが、101メソッド・約13,500行を書き写す手間に対して、得られるのは
「Reborn のコードを配る量が8割減る」だけで、配ること自体は変わらない。しかも写した
メソッドは Reborn 本体が更新されるたびに陳腐化する（現在の丸ごと差し替え方式も同様に
陳腐化するが、差分を取れば追従できるのに対し、写しは元がどう変わったか分かりにくい）。

次のいずれかになったら再検討する。

- Reborn 側が base game の差し替えを明確に禁止した
- 配布物から Reborn のコードを完全に除く必要が生じた（8割減では足りない場面）
- 対象メソッドが大幅に小さくなった（現状の最大は `Battle_MoveEffects.rb` の 4,042 行）

### 移行前に決めること（再検討する場合）

本パッチの変更には**翻訳以外のもの**が混ざっている（`Load.rb` のセーブ破損時の処理、
`System.rb` の `Input::E` / `Input::F` の `defined?` ガード、`Reborn/Settings.rb` の
`NOSIGNPOSTS`）。これらを Mod 側へ持っていくのか、そもそも配布物に含め続けるのかは
翻訳とは別の判断になる。
