# ストーリー会話 翻訳ガイド（全エージェント共通）

Pokémon Reborn（RPG Maker XP / Pokémon Essentials）の英語テキストを日本語化する作業。
UI・システム系はすでに完了・出荷済み。残りはマップ上の会話。

## 入出力

- 入力: `jp_translation/work/batch/g<N>/g<N>_XXXX.tsv`
  1行1件、タブ区切り3列 = `id`, `話者名（空のことが多い）`, `英文`
- 出力: `jp_translation/work/answers/g<N>_XXXX.tsv`
  1行1件、タブ区切り2列 = `id`（入力からそのままコピー）, `日本語訳`

入力の英文を出力に書き戻さないこと。id と訳文だけ書く。
入力1行に対して出力1行。行を落とさない。順序も入力どおりに。

## 参照ファイル

- `jp_translation/work/glossary.json` — 公式日本語名。
  `species` / `moves` / `abilities` / `items` / `types` / `trainer_types` の6セクション。
  英語名が本文に出てきたら必ずこの表の訳語を使う。
- `jp_translation/work/glossary_extra.json` — 上の表の補遺。

  **重要**: glossary.json はゲーム内のポケモン／わざ／どうぐの**データから**生成しているため、
  会話文の中でしか言及されないものは載っていない（第9世代のポケモンなど）。
  表に無いからといって Reborn 独自のものとは限らない。判断は次のとおり:

  - 実在するポケモン・わざ・どうぐ → **公式日本語名を使う**（表に無くても）。
    新しく確定させたものは `glossary_extra.json` に追記して次の担当者へ渡すこと。
  - Reborn オリジナルで公式名が存在しないもの → 自然な日本語に訳す。
- `jp_translation/work/speaker_map.json` — 英文 → `[話者, トレーナー種別, ID]`
- `jp_translation/work/speech_ja_batch1.json` 〜 `batch6.json` — 承認済みの口調サンプル。
  同じキャラのセリフは必ずこの口調に揃える。迷ったら該当キャラの既訳を grep して合わせる。

## 訳文の規則

1. **プレースホルダと制御コードは英文と完全に同じものを、同じ個数だけ残す。**
   `\PN`（主人公名）, `\v[12]`, `\c[3]`, `{1}`, `\b`, `\l` など。
   これは機械検証されるので、1つでも欠けるとその行は破棄される。
2. **常用漢字のみ。** 表外漢字は使わない（例: 溢れる→あふれる、掴む→つかむ）。
   検証は `python3 jp_translation/tools/check_joyo.py`。
3. **全角スペース（U+3000）を単語区切りに使わない。** 漢字が入るので不要。幅の節約が目的。
4. 行頭の `NAME:` は話者ラベル。`ジュリア:` のようにカタカナ表記＋半角コロンにする。
   人名の表記は `jp_translation/work/names_ja.json`、地名は `places_ja.json` に従う。
5. 口調は見た目・立場から推測して訳し分ける（承認済みシート準拠）。名前のない村人などは
   年齢・職業に合わせた普通の口調でよい。
6. メッセージウィンドウは2〜3行なので、冗長にしない。原文が短ければ訳も短く。
7. 罵倒・下品な表現はそのままの強度で訳す（原作の性格描写なので薄めない）。
8. 英文がそのまま日本語として通る場合でも、英語を出力に残さない。
   記号のみ・数値のみの行はそのままコピーしてよい。

## 進め方

- 担当グループのバッチを番号順に1ファイルずつ処理する。
- 1バッチ訳し終えるごとに `jp_translation/work/answers/` に書き出す（途中で止まっても失われない）。
- すでに `answers/` に同名ファイルがあるバッチは飛ばす。
- 全バッチ終了、またはコンテキストが厳しくなったら、最後に完了したバッチ番号を報告して終了する。

## 検証は自分でやらない

常用漢字チェック・全角半角の統一・表記ゆれは、書き戻し側の後処理ツール
（`dejoyo.py` / `apply_batch.py`）が一括で機械処理する。
エージェントが1行ずつ確認するとトークンを大量に消費するので、
**検証コマンドを自分で走らせないこと。**

あなたが守る必要があるのは1点だけ:
**プレースホルダと制御コードを英文と同じ個数だけ残す。**

これも「訳しながら気をつける」だけでよく、**確認のためのコマンド実行は不要**。
実際に消費が大きかったのは次の作業なので、どれもやらないこと:

- `apply_batch.py --dry-run` / `check_joyo.py` の実行
- 常用外漢字を1行ずつ手で直す（`dejoyo.py` が一括処理する）
- `diff` や `grep` で id 列・行数・プレースホルダ数を突き合わせる
- 監査用スクリプトを自作する

書き出したら次のバッチへ進んでよい。取りこぼしは私の側の後処理が検出して報告する。

### 検証を通すために原文を改変しないこと

過去に実際に起きた事故。どちらも後処理側で対応済みなので、回避策は不要:

- `\nTrain your mind` のように制御コードの直後に空白なしで英単語が続く箇所で、
  `\nTRAIN` までをプレースホルダだと誤解し、訳文に英単語を残してしまった。
  **`\n` は制御コードで、直後の英単語は本文。普通に訳す。**
- `GTS` や `xxxxxxxxxxx` のように訳す必要のない行を、
  「英文をそのまま返すと弾かれる」と考えて全角文字（ＧＴＳ）に置き換えてしまった。
  **記号・略号・数字だけの行は原文のままコピーしてよい。**

判断に迷う行があれば、無理に加工せずそのまま出して、報告に一言書いてください。
